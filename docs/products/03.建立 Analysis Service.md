你现在负责 data-ai-analyst 项目的第 3 个小任务。

目标：
在 Mock Domain 之上建立 Analysis Service。

本任务不修改页面，不实现 Pinia，不实现真实 HTTP API。

架构必须保持：

View
→ Pinia
→ Service
→ Mock Domain

未来替换成：

View
→ Pinia
→ Service
→ HTTP API
→ Python Backend

请先阅读：
- AGENTS.md
- CONTEXT.md
- 当前 Analysis Domain
- 当前 frontend/src/services

如果 services 目录不存在，请创建。

建议：

frontend/src/services/analysisService.js

提供：

1. createAnalysis(payload)

payload：

{
  question,
  context
}

返回新 Analysis。

2. getAnalysis(id)

3. listAnalyses()

4. runAnalysis(id)

注意：
MVP 这里只负责改变 analysis 状态为 running。
不要在 Service 内实现复杂 runner。

5. retryAnalysis(id)

6. cancelAnalysis(id)

7. getAnalysisResult(id)

8. drillDown(id, dimension, value)

MVP：
可以直接从已有 AnalysisResult 中生成 mock drill-down 数据。

9. getEvidence(id)

返回 Business Evidence 和 Technical Details 所需要的数据结构。

10. getTrace(id)

返回 Agent Trace mock 数据。

11. generateReport(id)

返回 reportId。

重要设计：

Service 必须成为 View 与 Mock Domain 之间的边界。

禁止：
- View 直接 import mock domain
- Service 操作 DOM
- Service 操作 Vue Router
- Service 操作 ECharts
- Service 依赖具体页面组件

不需要：
- FastAPI
- LangGraph
- MCP
- LLM
- DuckDB
- 真数据库
- HTTP request

所有数据仍然来自 Mock Domain。

完成后：
1. npm run build
2. 检查 import/export
3. 不修改任何 View
4. 不新增 Pinia
5. 总结 API/service 方法。

不要重构无关代码。
